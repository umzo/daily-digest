# ドキュメント構成ルール

## 現在の docs ディレクトリ構成

```
docs/
├── DESIGN.md                      # システム設計書
├── IMPLEMENTATION_PLAN.md         # 実装計画書
├── TEST_PLAN.md                   # テスト計画書
└── spec/
    └── daily-digest/
        └── requirements.md        # 要件定義書
```

## 各ドキュメントの役割

### DESIGN.md（システム設計書）
- **目的**: システム全体のアーキテクチャと設計判断を記述
- **内容**:
  - システム概要と要件
  - システム構成図
  - コンポーネント設計
  - データフロー
  - AWS リソース設計

### IMPLEMENTATION_PLAN.md（実装計画書）
- **目的**: TDD に基づく実装順序と計画を記述
- **内容**:
  - 実装順序の方針（ボトムアップ）
  - フェーズ別の実装タスク
  - 依存関係と被依存関係
  - チェックリスト形式のタスク管理

### TEST_PLAN.md（テスト計画書）
- **目的**: テストコードの構成と各テストケースを記述
- **内容**:
  - テストファイル構成
  - コンポーネント別テストケース一覧
  - テスト観点と期待動作

### spec/daily-digest/requirements.md（要件定義書）
- **目的**: 機能要件・非機能要件を網羅的に定義
- **内容**:
  - 機能要件（Fetcher, Summarizer, Formatter, Publisher）
  - 非機能要件（パフォーマンス、コスト、可用性）
  - 信頼性レベル（設計書根拠、推測など）

## ドキュメント作成ルール

1. **言語**: 日本語で記述
2. **形式**: Markdown 形式
3. **構成**: 目的 → 概要 → 詳細の順で構成
4. **表記**: 技術用語は英語、説明文は日本語
5. **更新**: 実装と同期してドキュメントも更新する
